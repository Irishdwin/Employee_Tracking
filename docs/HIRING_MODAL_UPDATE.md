# Applicant Contracts and hiring modal update

1. **Files modified:** `Html/HR/applicant_contracts.html`, `Html/HR/employee_conversion.html`, `Html/Admin/admin_dashboard.html`, `Html/HR/hr_dashboard.html`, `Js/HR/hr_dashboard.js`, `Api/Admin/process_hire.php`, `Api/HR/convert_to_employee.php`, and the isolated `Testing/ClientCompanies/http_test.php` harness.
2. **Files created:** `Css/hire_modal.css`, `Testing/ClientCompanies/hire_modal_test.cjs`, and this report.
3. **Convert removal:** removed the Applicant Contracts row button and its exclusive navigation handler. Open Contract and Replace Contract remain. Employee Conversion retains Hire Applicant and the shared hiring backend.
4. **Modal layout:** the embedded conversion page previously centered its modal within a tall iframe below the dashboard header. The same modal node now uses the parent dashboard's Bootstrap implementation and viewport. Scoped styling plus centered/scrollable Bootstrap classes keep the content bounded; the body scrolls while header/footer remain accessible. Bootstrap handles background scrolling and restores it on close. Standalone conversion retains its own Bootstrap instance. Parent-owned modal nodes are cleaned up on iframe navigation.
5. **Monthly Allowance:** removed labels, inputs, prefixes, reset variables, validation and request properties from the hiring UI. Backend allowance compatibility remains: omitted allowance defaults to zero. Existing employee allowances and payroll usage are preserved.
6. **Sunday Duty Allowance:** retained in conversion and made available in the native Admin/HR hiring forms. Fixed the Admin HTTP endpoint's missing forwarding of this value to the existing helper.
7. **Salary calculations:** existing preview logic and `employee_salary_helper.php` remain unchanged. Daily rate / 8 gives hourly rate; daily rate * 26 gives monthly salary credit. Actual HTTP tests verified 800 -> 100 and 20800.
8. **Backend/database:** no migration or destructive data changes. Hiring/account/deployment/government-ID persistence and notification helpers remain. The actual Admin HTTP test exposed obsolete employee/notification column names after employee creation; these were corrected to real name columns and the existing notification helper. The HR endpoint now uses the shared session initializer and retains database-backed Admin/HR authorization. Existing Admin hire audit logging remains; the HR conversion endpoint did not previously contain the equivalent audit call and this change does not introduce duplicate logs.
9. **Testing:** browser interaction tests use actual frontend/components with controlled API responses and an embedded dashboard harness, exercising Admin and HR contexts at 1920x1080, 1366x768, 1024x600 and 390x640. They check modal bounds, header/footer/X/actions, salary previews, omitted allowance payload, close/scroll restoration, missing Convert, retained contract link and Replace Contract dialog. Real Admin and HR HTTP hires run in a disposable schema copied from the production schema, with synthetic accounts/applicants; the existing Sunday allowance/payroll regression suite was also run. PHP/JS syntax and diff whitespace checks passed.
10. **Results:** 67 isolated API checks passed, including actual Admin/HR hire and saved salary/Sunday amounts. The existing Sunday allowance suite passed 44 checks. All 64 combined browser viewport, hiring and contract-action checks passed.
11. **Limits:** browser responses are controlled fixtures; persistence and authorization are independently exercised by actual isolated HTTP requests. No live applicant was hired as a test, and no production data was removed. The Open Contract test verifies the retained link, not the contents of a real uploaded contract. An editing encoding error temporarily emptied Admin HTML; it was recovered from the latest matching workspace snapshot, retaining prior Client Companies/contact changes before reapplying this task's edits.
